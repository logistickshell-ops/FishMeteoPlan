# ФишМетеоПлан

Telegram Mini App для прогноза клёва рыбы по погоде, городу и типу водоёма.

## Возможности

- поиск города через Open-Meteo Geocoding API;
- текущая погода и фактическая температура воды только при наличии измерения;
- фактическая погода за вчера;
- сегодня, завтра и прогноз на 7 дней;
- локальный расчёт оценки клёва для видов рыбы и времени суток;
- каталог рыб, проверенных мест, узлов и раздел «Подготовка+»;
- Telegram Mini App: `ready`, `expand`, приветствие пользователя и haptic feedback;
- сезонный fallback, если Open-Meteo временно недоступен;

Погода загружается напрямую из бесплатных API Open-Meteo, API-ключ не требуется.


## Render Static Site

В Render создайте **Static Site** из GitHub-репозитория:

- **Build Command:** `npm ci && npm run build`
- **Publish Directory:** `dist`
- **Auto-Deploy:** включить для автоматических деплоев из GitHub

Готовый `render.yaml` в репозитории содержит те же настройки.

## Telegram Mini App

1. Создайте бота через [@BotFather](https://t.me/BotFather).
2. Опубликуйте приложение на Render по HTTPS.
3. Выполните `/newapp` и укажите URL Render как Web App URL.
4. В `Bot Settings → Menu Button` укажите тот же URL.

Важно: Telegram передаёт данные пользователя в `initDataUnsafe` для UI. Если в будущем понадобятся авторизация, синхронизация или сохранение данных на сервере, `initData` нужно проверять на backend по правилам Telegram.

## Ограничения текущей версии

Показатель клёва — **индекс условий 0–100**, а не статистически откалиброванная вероятность улова. Журнал уловов хранится только в `localStorage` конкретного браузера/Telegram WebView. Для настоящей вероятностной модели нужен проспективный региональный журнал с усилием ловли, нулевыми выездами, источниками гидрологии и неизменяемыми weather snapshots.

## Алгоритм прогноза

В проекте используется `src/algorithm/forecastEngine.ts`. Это детерминированное TypeScript-ядро, адаптированное под статический Telegram Mini App; отдельный FastAPI-сервис не добавлялся, чтобы сохранить согласованный deployment на Render Static Site.

Ядро принимает погоду Open-Meteo, тренд давления за 3 часа, порывы ветра, осадки за 24 часа, влажность, тип водоёма и астрономические параметры. Водные входы разделены по происхождению: без датированного измерения температура воды, DO, мутность и уровень не считаются фактом и не получают скрытую замену погодой. Эвристики включаются только при нейтральном базовом score `[0.40, 0.60]`; их общий сдвиг ограничен `±0.12`.

Результат содержит индекс, покрытие входов, reasoning и тактические рекомендации. UI явно сообщает об отсутствии статистической калибровки и показывает региональный маяк. В период нерестовых ограничений прогноз на выбранную дату блокируется. Народные приметы не являются самостоятельным источником данных и не могут доминировать над базовым скорингом.

Проверка ядра:

```bash
npm run check:algorithm
```

Чек-лист приёмки находится в `ALGORITHM_CHECKLIST.md`.

## Региональные маяки Ярославской области

`src/data/regionalBeacons.ts` содержит пять доказательно описанных объектов: Волга/Горьковское водохранилище у Ярославля, Которосль, Рыбинское и Угличское водохранилища, Плещеево озеро. Маяк задаёт тип водоёма, подтверждённые факты, необходимые измерения, правовые шлюзы, ограничения и источники. Он не добавляет выдуманные проценты: неизвестные гидрологические входы остаются `missing`.

Подробный контракт и границы применимости находятся в `REGIONAL_BEACONS.md`. Проверка слоя выполняется командой `npm run check:regional-beacons`.

## Водные данные

`src/services/hydrology.ts` подключает бесплатный Open-Meteo Flood API. Он возвращает модельный речной расход GloFAS с пространственным разрешением около 5 км и историей/прогнозом. Расход сохраняется с датой, координатами возвращённой ячейки и происхождением `modelled`; он не участвует в индексе клёва автоматически и не считается измерением на посту.

Для выбранного города Ярославль и речного объекта приложение дополнительно пробует получить таблицу гидрологических постов Ярославского ЦГМС (`src/services/yacgmsHydrology.ts`). В прогноз попадает только строка, сопоставленная с допустимым названием реки и содержащая источник; температура и уровень сохраняются с пометкой `measured`. Если строка или требуемый параметр не найдены, значение остаётся `missing`. Далёкий пост не подставляется автоматически для Волги в Ярославле.

Температура воды, растворённый кислород, мутность и уровень показываются как `missing`, если нет измерения в сопоставимом посту. Open-Meteo Flood не измеряет эти параметры. Таблица Ярославского ЦГМС используется как наблюдательный источник, а дата и ограничение публикации отображаются рядом с измерением. Другие постовые ряды должны быть сопоставлены с координатой и проверены по времени/QC до использования в прогнозе.

Для озёр ближайший речной расход намеренно не подставляется: расход реки около города не является расходом или уровнем озера.

После выбора города `src/services/waterSearch.ts` загружает ближайшие именованные реки, озёра и водохранилища из OpenStreetMap через Overpass. Водный объект можно найти по названию через Nominatim, выбрать отдельно и сохранить в профиле пользователя. После выбора гидрологический запрос выполняется по координатам водного объекта, а не по центру города. Публичные OSM-сервисы могут временно ограничивать частоту запросов; при ошибке приложение оставляет ручной поиск и не создаёт фиктивный объект.

Индекс условий отображается в пользовательском интерфейсе как процент (`71%`), но это по-прежнему индекс, а не вероятность улова. Давление Open-Meteo берётся из `pressure_msl` в гПа, хранится в исходных единицах и дополнительно переводится в мм рт. ст. коэффициентом `0.750061683`. Давление для каждого дня берётся из соответствующего часового значения, а не копируется из текущего состояния. Проверки: `npm run check:pressure`, `npm run check:water-search`.


## База проверенных мест

Файл `src/data/fishingSpots.ts` содержит публично описанные рыбные места и водоёмы для восьми городов: Ярославля, Рыбинска, Ростова Великого, Переславля-Залесского, Углича, Брейтово, Пошехонья и Тутаева. Поиск города выполняется через Open-Meteo, после выбора каталог фильтруется по нормализованному названию города. В карточках нет выдуманных координат: показываются водоём, виды рыбы, подходящие снасти, практическая заметка, условия доступа и источники.

Упоминание места не является гарантией бесплатного прохода, разрешённой ловли или улова. Перед выездом нужно проверить актуальные правила, режим частной территории или базы, подъезд, стоянку, состояние воды и безопасность.

## Подготовка+

Раздел «Подготовка+» заменяет пользовательский дневник в навигации. План хранится по Telegram ID в `localStorage` и включает дату из доступного недельного прогноза, время выезда (утро/день/вечер/ночь), отдельные периоды ловли, подробности выезда, снасти, предполагаемую рыбу и берег/лодку. Для выбранной даты отчёт использует соответствующий суточный ветер, порывы, осадки и давление. На основании выбранных значений локальный детерминированный отчёт подбирает наживку, прикормку, монтаж и крючки, время активности, тактику и меры безопасности.

Внешняя модель Qwen не вызывается из статического клиента: ключ API в Telegram Mini App раскрывал бы секрет. Для будущего ИИ-режима нужен защищённый серверный прокси с лимитами и передачей только проверенных входов; локальный отчёт уже работает без сети и не выдаёт модельные значения воды за измерения.

## Сезонные ограничения и снасти

Нерестовые ограничения рассчитываются функциями `isSpawningRestrictionActive` и `getActiveSpawningRestrictions`. В разделе «Инструменты и правила» подробный список показывается только в активное календарное окно; вне него отображается нейтральное напоминание сверить официальный документ для выбранного региона. Для прогноза на дату действует отдельный legal gate алгоритма.

Полный справочник основных снастей находится в `tackleGuide`: поплавочная удочка, фидер, пикер, спиннинг, джиг, ультралайт, воблеры и твичинг, кружки, жерлицы, мормышка, балансир и зимняя блесна, нахлыст/бомбарда, троллинг/дорожка, бортовая удочка и флэт-метод. Для каждой снасти указаны целевые виды рыбы, тип места, базовая оснастка и практический совет.
